# ADR-021：会话元数据与诊断存储

日期：2026-10-18。范围：M5-02；基线 M5-01 c9aba16。

## 决策

复用 Qt5::Sql/QSQLITE。RADCore 只依赖 ISessionRepository 抽象，RADPersistence 实现数据库；应用入口负责独占目录、初始化/迁移和重启清理。RADDiagnostics 仅接受固定事件与错误枚举；不装全局 Qt 消息处理器，不把终端原始流存盘。

元数据必须先保存才启动新进程。Agent 重启后的未终止记录转为 Failed/agent_restarted；所有导入记录均不可附加。存储不提供恢复 PID 或重启 Provider 的能力。

SQLite 迁移、恢复及历史裁剪使用事务；未知版本、损坏和写入失败明确报错，不自动重建或降级为无持久化服务。目录锁先于恢复，避免第二个实例误标仍活跃会话。

## 取舍

采用同步、低频生命周期存储，避免当前规模引入队列和异步事务框架；单次 SQLite 锁等待 1000 毫秒，后续压力测试须评估尾延迟。日志同步 flush，文件操作失败结束服务，避免长期静默丢失诊断。

数据库最多保留 128 条终态，活跃条目不裁剪。应用列表仍限制 32 项；新建时可淘汰未附加终态内存项。历史元数据不代表终端输出可恢复。

协议摘要/状态增加可选 diagnostics 对象，两端应配套升级；保留原有状态枚举，以 metadata_only 区分当前进程与历史记录。

## 验证依据

见 [M5-02 验收记录](../M5-02_会话持久化与运行诊断.md)。不承诺系统掉电恢复或旧 ConPTY 无损复活。

## Qt 5.15.2 有界接收缓存修复

Debug 回归复现了大历史回放中途断线，Qt 关闭码 1001、原因是读取数据超时。诊断发现 TCP 接收上限为 65536 字节，剩余半帧为 16270 字节；本机 Qt 源码中 QAbstractSocket 满缓存会关闭读取通知，QIODevice 只在缓存排空时重新启用，而 QWebSocketFrame 等完整负载才消费半帧，可能相互等待。

`core/transport/WebSocketReadBuffer.h` 统一处理两端：缓存为协议最大帧加 16 字节头空间，每个文本/二进制数据帧消费后通过公开 setReadBufferSize API 切换有限阈值并恢复，重新启用读取；Pong 及 Ping 自动回复的 bytesWritten 同样处理控制帧路径。帧和消息仍限制 64 KiB，没有放宽协议或设置无限缓存。测试同时覆盖 1 MiB 历史回放及 256 KiB 输入；临时诊断插桩已移除。

升级 Qt 后须先复测大历史与大块输入再决定是否移除此兼容处理，不依赖 Qt 私有 API。
