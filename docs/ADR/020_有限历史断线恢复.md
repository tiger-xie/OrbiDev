# ADR-020：断线后显式重连与有限历史重放

## 范围与决定

M5-01 复用同一 Agent 生命周期内的稳定 SessionId 和 SessionManager 的有界原始输出缓存。用户点击连接后重新获取会话列表，再从工作区打开原会话；不自动提交输入、不自动抢占写权、不重新创建进程。Agent/系统重启恢复不在本任务范围。

每次重新附加创建新的终端视图，从 Agent 当前保留的原始 VT 字节开始重放。不会向旧屏幕追加整段历史。没有终端状态快照，因此即使没有截断，也不承诺尺寸变化或全屏程序的精确画面重建。

首次输出之前允许接收一次既有 `terminal.overrun` 通知，记录起始偏移并严格校验随后的输出序号，使超过缓存上限的会话仍可附加。已开始输出后的缺口继续断开并提示重新附加，避免把不连续数据伪装成连续终端。

## 接口与分层

- `ClientSession.historyNotice` 是客户端显示状态，持久于当前会话的普通列表刷新，供窗口独立提示有限历史或截断风险。
- 真实恢复测试发现：重放历史 DA 查询会使 xterm 自动回复 `ESC[?1;2c`，污染当前输入。为修复这一实际问题，`SessionSnapshot.outputSequence` 提供累计输出尾偏移，`session.attached` 增加十进制字符串 `replay_end_sequence`。每个输出块携带其历史前缀字节数至终端视图，历史写入期间禁用输入和自动回复，写入确认后恢复。
- 保留 RADP/1 帧结构，不增加 `last_ack_sequence` 支持或依赖。旧客户端严格拒绝多余字段，新客户端拒绝没有回放边界的 Agent，双方需要配套升级；不以超时猜测历史结束，也不筛选某几个回复字符串冒充完整隔离。
- 终端输入保持只在连接且持有写权时发送；连接故障时结果未确认，不缓存或重试用户输入。

## 验证

真实 ConPTY/FakeCli 运行期间关闭网络监听并断开连接，保持一分钟；恢复原地址监听后重新查询、附加、输入，检查没有创建第二个后端。有限缓存超限及协议边界另由网络客户端测试覆盖。回环故障注入不等同于家庭 Tailscale 实测。
