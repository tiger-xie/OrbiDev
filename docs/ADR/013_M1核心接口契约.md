# ADR-013：M1 核心接口的错误、事件与线程契约

日期：2026-10-17。范围：TASK-M1-02；主计划第 5 节的接口草案细化，不实现 M2 会话服务或 M3 网络协议。

## 问题

原草案的 bool start、void writeInput/resize/stop 无法完整表达失败，也没有定义输出、退出的通知方式。SessionRequest 只有工作区标识，Provider 不能从中安全推导任意机器路径。若直接据此分别实现后端和上层，会出现错误丢失、线程阻塞或分离导致进程退出。

## 决策

- 核心模型与接口只依赖 QtCore 和标准库，沿用 RADCore 目标；协议 DTO 仍独立，M1 不定义网络序列化。
- 会话请求引用已登记工作区 ID。Provider 接收由授权/工作区层解析的可信工作区上下文；路径字段存在不代表已经执行白名单验证。启动参数保持数组，禁止作为未经校验的 shell 字符串拼接。
- 后端和会话管理采用抽象 QObject 与事件通知。普通成员函数仅在对象所属的 Agent 控制线程调用，不因继承 QObject 自动获得线程安全；UI/网络层必须通过受控调度跨线程。
- 方法必须区分请求接受、同步拒绝与异步完成。失败携带可区分错误码及脱敏说明；已接受的启动/终止由事件报告最终结果，不能用入队成功冒充进程已启动或退出。
- 输出以原始字节传递，输入排队和输出保留均须有界。跨线程通知不能逐块无限排队；截断必须明确通知。具体容量与工作线程实现留给 M2，但接口必须容纳背压行为。
- 选择合并的 outputAvailable 通知和 takeOutput 分批拉取，不在每个通知中携带字节；读取结果包含丢弃量和剩余数据标识。调用方以受控节奏排空，避免 queued 信号把有界缓冲重新变成无界消息队列。
- 进程状态与附加状态分开。detach 仅解除输出订阅/输入控制权，不调用后端终止；terminate 是显式操作。每个会话至多一个写者，输入与 resize 检查控制权。
- Creating 阶段允许经授权的创建主体显式取消，避免尚未取得写权时无法停止启动；正常取消可以直接 finished，不伪造 started 或启动失败。异步完成事件在请求返回之后交付，且 finished 位于尾部输出归并之后。
- 新订阅从当前保留缓冲起点读取，附加时已存在数据或截断量也须通知；重新附加视作新订阅。此为有界缓存的读取契约，不承诺 M5 的持久重放或精确恢复长会话画面。
- 接口注释明确参数所有权、事件线程、生命周期及重复调用语义；测试替身不拥有真实进程。
- Provider 是不进行磁盘/进程 IO 的同步参数转换接口；工具探测及路径授权由其调用边界先完成。SessionManager 的 clientId 表示授权层传入的主体，字符串本身不是认证证明。

## 取舍与影响

拒绝保留 void 操作再靠日志推断成功：调用方无法可靠反馈错误。拒绝提前创建真实 SessionManager、Provider 注册或文件传输服务：超出当前任务。拒绝为 future/结果类增加第三方依赖：QtCore 与标准库足够。

主计划第 5 节示例仍作为最初设计参考，实施时以 core 头文件和本决策为准。接口暂未用于持久化或对外网络传输，无既有协议兼容迁移。M2 必须以真实 ConPTY 验证线程、队列、退出和单写者行为；M1 的 Mock 测试不能代替这些验证。
