# M3-01 RADP/1 协议编解码

## 范围与入口

基线为 M2-02 与调试修复提交 `1991340`，本轮在 `codex/m3-protocol` 工作区实现。协议库同步处理值对象，不启动服务器、不访问文件、不修改会话。RemoteAgent 仍按原工程入口运行；本轮不能直接连接家庭电脑。

## 调用链

控制消息走 `decodeJson → 认证/授权（M3-02）→ validateSession（需要会话的操作）→ SessionManager（M3-02 路由）`。返回 DTO 通过 `encodeJson` 编码，终端原始字节通过 `encodeBinary/decodeBinary` 编解码。

所有函数同步返回；失败时检查 `Error`，不得使用输出值作为成功结果。失败不覆盖调用方原有结果，成功时无需读取旧 Error。无可变全局状态，不同线程可以使用独立参数调用；共享输出对象须由调用者同步。

JSON 与二进制消息的总字节数均不得超过 65536。二进制头固定 34 字节，有效载荷最多 65502 字节，UUID 使用 RFC 4122 字节顺序，序号和长度使用大端整数。完整消息长度必须与声明一致，额外尾部同样拒绝。输入输出为不透明原始字节，可包含 NUL、ANSI 或分割的 UTF-8 字符。

文本 UUID 使用小写、无花括号的规范形式，拒绝全零 UUID。空 ID 与无效 ID 不等价：只有允许无关联请求/会话的消息才允许空值，编码为 JSON null。

`negotiateVersion` 从最多 16 个、每个范围 1..255 的版本号中选择受支持的 RADP/1；协商通过不等于认证通过。`validateSession` 使用调用方提供的已知会话集合区分无效 UUID 和不存在会话，不能代替工作区与会话授权。

`makeErrorEnvelope` 仅从枚举生成固定安全文案，不接受系统错误字符串。不要把原始请求、凭据、启动参数或底层异常附加到公开错误中。

## 控制消息规则

顶层字段固定为 `version/type/request_id/session_id/payload`，全部必填；payload 为对象。未知类型和未知字段拒绝，不隐式降级；本版扩展字段须同步协议和测试。JSON 必须为有效 UTF-8。计数使用无前导零的十进制字符串，范围为 uint64，避免 JavaScript/JSON 浮点数丢失精度。

| 类型 | request_id / session_id | payload |
|---|---|---|
| auth.hello / auth.welcome | UUID / null | versions 数组 / selected_version |
| session.create | UUID / null | name、provider_id、workspace_id、columns、rows |
| session.list / session.listed | UUID / null | 空对象 / sessions 数组 |
| session.attach / session.attached | UUID / UUID | mode 为 read_only 或 read_write；attach 可含 last_ack_sequence |
| session.detach / session.detached | UUID / UUID | 空对象 |
| session.terminate / session.terminated | UUID / UUID | 空对象 |
| session.resize / session.resized | UUID / UUID | columns、rows / 空对象 |
| session.heartbeat / session.heartbeat_ack | UUID / UUID | 可选 last_ack_sequence / 空对象 |
| session.created | UUID / UUID | process_state、attachable |
| session.status | null / UUID | process_state、attachable |
| terminal.overrun | null / UUID | next_sequence、dropped_bytes 十进制字符串，丢弃量大于 0 |
| error | 可为 null / 可为 null | error 对象内固定 code、message、retryable |

名称最长 256 个 QString 字符，Provider 与工作区 ID 最长 128，均非空且不含 NUL；终端列/行是 1..32767 的整数。列表最多 128 项，禁止重复会话 ID；每项包含 session_id、name、provider_id、workspace_id、process_state、attachable。进程状态为 creating/running/exiting/exited/failed。

`auth.hello/welcome` 在本阶段仅表达协议协商，尚无认证凭据交换。`session.terminated` 在路由层接入时表示显式终止请求已受理，最终进程状态须等 SessionManager 事件，不可提前宣称进程已经退出。二进制 kind=1 为输入、kind=2 为输出，空载荷拒绝；连接层无数据时不发送终端帧。

主计划建议清单中的 `host.info/workspace.list/system.capabilities` 尚未定义 payload，本版将其作为未知类型拒绝，待相应业务任务同步定义与测试。终端输入只采用二进制 kind=1，不同时支持 JSON terminal.input。

## 验证边界

本阶段验证编解码和独立会话存在性检查。WebSocket 接收缓冲上限、鉴权、重复请求、序号单调性、重放及连接队列由 M3-02 和后续恢复任务实现；本次随机变异测试不等于覆盖引导的持续模糊测试，也不能证明网络层已经安全。

复验命令（在 VS 开发环境或已配置 CMake 的终端执行）：

```powershell
cmake --preset local-msvc
cmake --build --preset debug --target RADProtocolTests
ctest --preset debug -R '^protocol\.codec$'
cmake --build --preset release --target RADProtocolTests
ctest --preset release -R '^protocol\.codec$'
```

测试覆盖所有本版消息类型、独立二进制黄金样本、64 KiB 边界、损坏长度/版本/UUID、uint64 极值、非法 UTF-8 与孤立代理项、合法中文/emoji、会话列表重复 ID、不存在会话、安全错误、失败不覆盖结果及 3000 轮定种子变异输入。
