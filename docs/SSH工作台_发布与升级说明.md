# OrbiDev SSH 工作台：候选包、升级与验收

版本：0.1.0-preview。当前产物用于本地和真实双端验证，尚未达到正式发布门槛。

## 启动与范围

解压到一个新的目录，双击 `Start-OrbiDev.cmd` 启动客户端。首次使用从“连接设置”打开配置向导；在家庭电脑运行 `Start-HomeSetup.cmd` 完成一次公钥授权。家庭端工具不需要常驻，家庭电脑的 sshd 与 Tailscale 需要可用。

开发目录也使用根目录 `Start-OrbiDev.cmd`；原 `Start-SshWorkbench.cmd` 保留兼容。版本可在窗口标题、`--version` 或“连接设置 → 关于 SSH 工作台”查看；构建来源、测试结论、文件校验信息以包内清单为准。

链路为 Qt 内嵌终端 → 本地 ConPTY → 系统 OpenSSH → 家庭 Claude。便携包不附带 Tailscale、Windows OpenSSH Server 或 Claude，不保存或传递 Claude 登录信息。原 Client/Agent 暂停开发，不属于此包的启动流程。

关闭工作台、关闭标签或网络断开都不保证远程任务继续。重新连接创建新会话，不恢复原进程。主机指纹与 Claude 工作区信任需要本人核对，不自动确认。

## 升级与回退

1. 保存远端工作，再关闭工作台。不要在有活动任务时直接覆盖正在运行的程序。
2. 备份当前项目目录中的 `projects.json.workbench.json` 与 `projects.json.preferences.json`，以及使用过的旧 `projects.json`、连接配置和迁移备份。自定义 `--projects` 时以实际路径为准。默认位置由当前 Windows 用户的 Qt 应用配置目录确定。
3. 将新包解压到新目录，不把新旧 DLL 混在同一个目录。用户配置与便携程序目录分开，正常升级不需要重建身份或重新授权。
4. 启动后核对主机、项目归属与字号。程序只恢复选择，不自动启动 Claude；显式打开项目后再核对真实目录。
5. 需要回退时先保留当前配置副本，再启动旧版本。旧版本不一定识别新档案，不要让旧版本直接覆盖新格式；按对应版本说明使用备份，避免混用配置。

旧单主机配置首次迁移会保留原文件并创建 `.ssh02.bak` 备份，再原子保存多主机档案。损坏、版本不支持或备份冲突时会停止，不猜测主机归属。独立偏好损坏时保留原文件并提示，本次运行不覆盖。

私钥是身份凭据，不属于安装包或普通问题报告。不要把用户配置、密钥、`known_hosts` 或真实终端日志放入待分享的压缩包。需要协助时优先使用“复制脱敏诊断”。

## 打包与依赖检查

打包脚本白名单收集三份程序、服务启动脚本、Qt 动态库与插件、WebEngine 子进程／资源／语言文件、ConPTY 运行库与 `x64/OpenConsole.exe`、运行库、说明及实际许可文本。每次使用独立的新目录，不从旧发布目录增量拼接。

常规构建测试失败会停止。只有显式候选模式才允许携带失败或未执行结论生成候选包；候选包名称、清单和说明必须保留该结论，不能作为测试通过的替代证明。正式分发还需要完成下表的验收和许可义务检查。

附带 Qt、Chromium、ConPTY、xterm.js 与 fit-addon 的许可文本。文件存在性及哈希校验只说明内容随包提供，不等于已经完成全部第三方分发义务审查。Qt 候选补丁未应用，不能在版本说明中声称 Qt 原生问题已修复。

Release 构建通过；完整 CTest 为 9/10，SshSession 的内嵌终端初始化超时仍失败。打包校验夹具 5 项通过，实际包 79 项文件哈希通过。候选包 `manifest.json` 保留 `testStatus: Failed` 与 `acceptanceComplete: false`。
