# OrbiDev SSH 工作台：分支开发计划

版本：v1.0 · 更新：2026-10-18

适用分支：`codex/ssh-setup-wizards`。

本文件是本分支后续开发的任务入口。原 RADManager Client/Agent 里程碑继续暂停，保留现有代码和未提交工作，不把旧方案的完成状态计入本计划。

## 1. 产品目标与范围

在一个 Qt 窗口内管理家庭电脑、项目和多个 SSH 终端，直接操作家庭电脑上的 Claude。日常操作突出项目与终端，低频连接配置移入设置。沿用已选择的石墨灰／青绿视觉方向、标准 Windows 标题栏，集中维护外观，为后续换肤保留入口。

技术基线：Qt 5.15.2 MSVC x64、VS 2022/v143、C++20、CMake。先在本机 Windows 10 IoT 企业版 LTSC x64（19044）构建与验证，Windows 11 作为后续兼容环境。不额外提升业务代码语言要求，不为本计划新增无关依赖。

链路保持：Qt TerminalView → 本地 ConPTY → 系统 ssh.exe → 家庭 PowerShell → Claude。复用现有终端、ConPTY 和 SSH 身份／主机信任实现，不重新引入 Agent 协议、控制权租约、会话数据库或常驻配对服务。

本版不做：断线任务托管、原进程恢复、图片剪贴板上传、NAS/Git 集成、任意启动命令配置。重新连接必须说明会新建会话；不得替用户确认 Claude 工作区信任提示。

## 4. 任务卡

### SSH-01：打开已有终端，显式新建额外会话

目标：用户浏览项目不会误开多个 Claude。

- 双击项目：优先切换该项目已有的准备中／活动标签；没有可复用标签才创建。
- “打开勾选项目”：逐项复用或创建，重复点击不累积重复会话。可复用标签有多个时选择最近使用的一个。
- 右上角“新建终端”：始终为当前选中项目额外创建会话；不将此操作改成复用。
- 已退出或正在关闭的标签不复用；“复用”只限当前客户端中存在的标签，不表示远程进程恢复。
- 匹配基于稳定项目身份与创建时的连接配置，不只比较显示名或目录。同目录的不同项目允许独立存在；修改目录或连接配置后不误切回旧目标。
- 为项目补齐稳定 ID 时采用最小配置迁移，保留名称、目录、勾选状态和旧 `terminal_path`；读取失败不覆盖原文件。后续 SSH-02 再扩展主机 ID。

主要文件：`tools/SshWorkbench/WorkbenchWindow.*`、项目配置模型与对应测试；优先复用 `tools/ProjectLauncher/LauncherCore.*`，不改旧启动器的现有行为。

验收：连续双击／批量打开不重复创建；准备中也去重；显式新建仍可建立第二个会话；退出后可新建；同名不同项目不串标签；重命名和目录变更符合上述规则；旧项目配置可迁移且原文件保留。

### SSH-02：多主机档案与项目归属

目标：家庭笔记本、测试机等同时保存在列表中，新增不会替换已有主机。

- 主机拥有稳定 ID、显示名、地址、用户名、端口、身份文件路径、已核对主机指纹。私钥内容不进入档案。
- 项目绑定主机 ID；当前主机选择与标签创建时的主机快照分开。不同主机上的同名项目互不复用。
- 支持添加、编辑、选择、连接测试、导入家庭端连接信息；首次配置工具按指定主机更新，不覆盖其他档案。
- 同一公司端公钥可以用于多台家庭电脑，每台分别授权与核对主机指纹；不得以 Tailscale 在线替代授权。
- 从旧单主机 `connection.json` 及项目配置迁移：生成默认主机，绑定已有项目，重复启动不重复导入；备份旧文件，原子写入新版本。损坏或不支持的版本明确报错。
- 删除主机时列出关联项目和活动标签；存在引用时阻止直接删除，引导先处理引用，不静默删除项目或断开会话。修改主机不改变已打开标签。

验收：两台主机档案同时保存，切换／重启不丢失；同名项目正确归属；旧配置迁移可回退；新增和导入不覆盖其他主机；错误指纹拒绝连接；活动标签保持原目标。

### SSH-03：项目与标签联动、准确状态

- 左侧显示项目已打开的标签数量；选中标签时定位对应项目，项目切换行为与 SSH-01 一致。
- 同项目额外标签显示可区分编号；提示中包含主机、用户、远程目录。改名后项目身份不变。
- 标签区分：准备终端、校验主机、SSH 进程运行、正在关闭、已退出／失败。退出保留原因和退出码。
- SSH 已启动后不长期显示“正在连接”。不解析 Claude 屏幕来猜测任务状态，不声称认证或 Claude 就绪已被确认。
- 退出标签提供“重新连接”，明确新建会话，不自动确认工作区信任、不把新会话冒充恢复。
- 关闭确认可取消；确认框期间发生启动或退出也应正确收尾，界面不得等待网络探测而冻结。

验收：项目计数、焦点和标签一致；名称重复不混淆；失败信息可辨识；重新连接语义清楚；各类关闭竞态有自动回归测试。

### SSH-04：真实双端验收与稳定性修复

选择两个不同的家庭项目目录，并分别核对实际工作目录；具备两台已授权主机后增加跨主机测试。自动测试使用 FakeCli／测试替身，真实 Claude 验收由用户操作，不自动发送业务指令。

| 场景 | 验收标准 |
| --- | --- |
| 双项目、多标签 | 同时可用，输入不串会话，关闭其中一个不影响另一个 |
| 中文、退格、粘贴 | 输入过程及回显正常，无乱码、丢字或重复提交 |
| `/`、Tab、Esc、方向键、Ctrl+C | 与家庭端 CLI 操作一致，Tab 不误跳到外部控件 |
| 窗口尺寸、字号、100%／150% 缩放 | 行列同步，提示与内容不被遮挡，无明显布局错误 |
| 错误目录 | 明确失败，不能退回其他目录启动 Claude |
| 未授权密钥、超时、指纹变化 | 原因可诊断，不静默放行或显示成功 |
| 主动断网／恢复 | 显示实际退出或错误；新连接不声称恢复旧任务 |
| 持续输出与反复开关 | 至少一次 30 分钟运行、20 次创建／关闭循环；记录内存／句柄是否持续增长，缓冲溢出有明确反馈 |

逐项记录“已执行通过／失败／未执行”、环境、版本和证据；不能只写“验收通过”。发现缺陷先修复并回归，再进入下一任务卡。

### SSH-05：首次配置与家庭端诊断

- 公钥与指纹分开展示；粘贴 `SHA256:...` 时指出这是指纹，引导“复制公钥”或 `.pub` 导入；私钥与非法内容继续拒绝。
- 显示主机名与当前用户，减少在另一台家庭电脑操作时套用旧配置的误会。
- 统一连接与服务检测结果，可复制脱敏诊断，区分未安装、未运行、端口不可达、认证失败、指纹不匹配。
- 补全 OpenSSH 安装／启动引导。已有正常环境仅追加授权；不自动更改 Shell、重启服务或扩大防火墙范围。
- 本卡先完善引导，不默认承诺自动系统安装。若实现自动安装／访问规则，须单独列变更清单、用户确认与 UAC、配置备份及校验失败回滚，并限定 Tailscale／回环访问；未经该验收不能标为完成。

验收：首次使用者不需猜公钥格式；错误导入说明具体；启动服务支持确认／取消；安装失败保留原因；普通／管理员账户、现有自定义配置均有明确处理边界。

### SSH-06：日常体验和外观设置

- 保存窗口位置、大小、项目栏宽度和字号，恢复时处理屏幕分辨率变化。
- 外观设置集中管理，保留主题扩展入口；先保证现有深色样式完整，再按实际需求增加皮肤，不预先堆主题框架。
- 完善空状态、错误状态、正在关闭状态、快捷键提示及焦点顺序。
- 保存最近选择的主机和项目，但默认不自动启动远程 Claude。

验收：重启后偏好正确恢复；100%／150% 缩放可用；错误与禁用态清晰；不影响终端输入或现有配置。

### SSH-07：发布整理

- 统一客户端启动入口，配套家庭端一次性工具，提供版本信息、升级与迁移说明。
- 打包 Qt WebEngine 辅助进程、资源、插件、ConPTY 和许可；在 PATH 不含开发 Qt 的环境验证。
- 使用新的用户环境测试首次配置、旧版本配置迁移、日常启动；补充 Windows 11 兼容检查记录。
- 同步文档、任务状态和已知限制；清楚区分 SSH 工作台和暂停的 Client/Agent。
- 提交仅包含本分支相关文件；原有 M5-02 等工作区改动不混入。提交遵守仓库 Lore 协议，推送需明确请求。

发布门槛：SSH-01 至 SSH-06 的约定范围完成或有明确延期记录；SSH-04 关键场景有证据；构建与测试通过；未执行项、已知风险公开记录，不称为“全部功能完成”。
