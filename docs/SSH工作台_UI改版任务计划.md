# OrbiDev SSH 工作台 UI 改版任务计划

日期：2026-10-20。分支：`codex/ssh-setup-wizards`。

## 目标与验收方式

按用户提供的后四张产品图改造真实 Qt Widgets 程序，覆盖首次设置、家庭端授权、工作台、项目弹窗与失败状态。前两张截图是现状，不作为视觉目标。采用 Product Design 的参考图拆解与对照流程，以及 qt-widgets-product-design 的布局、资源和实际窗口验收方法；实现仍使用 Qt 5.15.2 / v143 / C++20，不转为网页原型，不新增第三方依赖。

本轮先交付模块任务计划（UI-00）。之后逐项实现、构建、截图检查、记录差异，再进入下一项。自动化可判断的检查直接执行；人工项提供具体页面与操作，不以“看起来不错”作为验收标准。每项完成时提供真实截图供用户检查；用户提出偏差时优先修正当前项，不继续扩大改造范围。

已有超时诊断修改、ProjectLauncher 等无关修改保留。UI 任务不自动提交或推送，也不把 Release 偶发超时、Debug Qt 原生问题列为已解决。

设计方向：

- 石墨色背景与略亮的侧栏、表单表面区分层次；终端是最深的主要工作区域。
- 青绿色只强调当前步骤、当前项目、活动标签和主要操作；红色配错误图标与文字，不能仅靠颜色表达状态。
- 向导优先“当前要做什么”，以分区和对齐组织信息，避免页面上散落文本与按钮。
- 工作台优先终端面积；设置、外观和低频操作集中，项目附近保留增删改入口。
- 文字有标题、正文、辅助信息三个层次；图标采用一致的线性风格，常见操作也提供 tooltip 和可访问名称。
- 渐变与圆角适度还原；不增加模糊、透明背景或背景图片来模拟材质。

### 资源与职责约定

1. 新图标放在 `/resources/icon/对应模块/`，例如 `common/`、`setup/`、`workbench/`。优先自行绘制简单线性 SVG，记录来源；不使用字符或 emoji 代替产品图标。
2. 大段 QSS 放在 `/resources/style/`，建议 `base.qss`、`setup.qss`、`workbench.qss`，以实际需要为准。
3. 根目录 `/OrbiDev.qrc` 显式登记资源；使用 `:/resources/icon/...` 与 `:/resources/style/...` 调用，不读取源码绝对路径。
4. 根资源接入现有 `SshSetupUi`，工作台通过现有依赖复用。处理静态库资源初始化，验证两个独立 CMake 入口均可构建，防止重复链接与资源被裁剪。
5. 继续由 `applySetupTheme` 作为公共主题入口；按角色属性和局部对象选择器控制差异，不再创建第二套全局主题。
6. 动态错误/选中状态通过属性与必要的 repolish 切换；布局由 Qt 布局管理器负责，不用 QSS 假装布局系统。
7. xterm 的网页 CSS 保留在既有终端资源里；它与 Qt QSS 是两个绘制层，不重复搬入根 QSS。
8. 改造前以现有测试与截图固定行为；只删除已被资源文件替代的样式，不混入业务清理。

## 参考图与真实能力的差异

| 图中内容 | 实现约束与处理 |
| --- | --- |
| “SSH 已连接” | 现有 `started` 仅表示本地 ssh 进程启动。当前使用“SSH 运行中”，不能据此显示远端认证成功或 Claude 就绪 |
| “SSH 认证未通过” | 仅在有明确认证失败证据时显示；退出码 255 不能单独证明认证失败，未知原因显示“SSH 已退出”并保留输出 |
| “切换用户” | 当前授权工具针对当前 Windows 用户；本次不新增跨账户授权。展示当前用户与切换 Windows 登录用户的说明，不放无效按钮 |
| “设备备注” | 先检查现有公钥 comment/存储契约；无安全落点时只展示现有备注，不为截图新增持久化字段 |
| “保存后打开终端” | 属于明确的交互增量，放在 UI-06；仅用户勾选且保存成功后启动，取消、失败与编辑默认不自动启动 |
| 深色自绘标题栏 | 放在 UI-02 单独实现与验收；拖动、缩放、最大化、系统菜单和关闭确认必须保留 |
| 参考图样例用户名、路径、指纹 | 只用于明确标注的无副作用预览；正式界面来自配置与实际结果 |
| 重连 | 始终创建新会话，不承诺恢复远端原任务 |

### UI-01：先落资源与公共控件

- 拟改：根 `OrbiDev.qrc`、`resources/style/*`、`resources/icon/*`、`SetupTheme.cpp`、两个工具 CMake、工作台内联样式入口。
- 清理计划：先保留现有选择器对应关系；移出 QSS 并确认行为不变，再调整调色、字体、边框与状态；删除被替代的字符串，不新增通用主题框架。
- 验证：已有向导、主机弹窗、工作台测试；资源存在与加载测试；三程序 Release 构建；公司端/家庭端/工作台各一张实际截图。
- 此项只建立基础，不将仍未重排的页面宣称为“参考图还原完成”。

### UI-02：窗口行为是独立任务

- 优先复用系统窗口能力。自绘区域负责标题、图标和按钮；Win32 命中测试与系统行为集中在局部窗口辅助模块。
- 保留键盘焦点、可访问名称、任务栏图标、最大化边界与恢复位置；不修改 SSH 会话关闭策略。
- Windows 10 本机验收；Windows 11 Snap 等需要实机证据，不能由静态截图推断。
- 若系统行为无法可靠保留，记录阻碍并保留原生边框，不以截图相似度交换窗口可用性。

### UI-03 / UI-04：向导结构

- 步骤项包含圆形状态、名称、简短描述、连接线；已完成与当前状态来自业务结果，不能只按页码推断成功。
- 主区域由页标题、副标题、主要信息区、就近帮助组成；底栏固定，上一步为次操作，下一步为主操作。
- R1 的身份摘要和三步家庭授权说明、R2 的用户摘要与公钥编辑区重点对齐。
- 其余页面依据同一规则补齐：环境检查项、身份创建结果、连接表单、授权变更摘要和导出结果。
- 长诊断可展开/滚动；关键错误保持可见，不能被固定底栏遮住。

### UI-05 / UI-06 / UI-07：工作台结构

- 顶部：主机选择、当前标签所属主机与状态、设置菜单、新建终端。切换浏览主机但保留旧标签时，两者不能混为一个状态。
- 左侧：项目标题与新增入口、名称与目录分层、勾选状态、选中状态、底部批量打开；编辑/移除放上下文入口并保留键盘可达性。
- 主区域：标签行、主机/目录信息条、终端；无标签时提供清晰空状态；已退出标签可查输出。
- 项目弹窗：名称→家庭主机→远程目录→打开选项→提示→取消/保存；编辑现有项目不移动或替换已运行会话。
- 错误横幅：错误图标、标题、说明、就近操作；设置入口指向失败标签的主机，不能误编辑当前下拉框选择的另一主机。
- 状态栏：编码与快捷键提示适度呈现；关闭/断线风险提示保留，必要时收纳到可发现的说明中。

## 每项验收记录模板

| 记录维度 | 必填证据 |
| --- | --- |
| 文件与职责 | 修改文件、资源路径、选择器映射、是否触及业务接口 |
| 静态 | qrc 引用、QSS 加载、格式与差异检查、无敏感示例数据 |
| 构建 | Qt 5.15.2 / v143 / Release，实际构建结果；不可把 Debug 标为已通过 |
| 功能 | 本任务受影响测试与手工操作；失败/未执行逐项列明 |
| 视觉 | 参考图标识、实际截图路径、窗口逻辑尺寸、100%/150%、已观察差异及修正 |
| 决定 | 已验收或待修项；下一项任务；是否需要用户实际双端配合 |

视觉检查至少包括：常规窗口、可用桌面内的窄窗口、长主机名、长中文项目名、长路径、空列表、失败、禁用、焦点。150% 下按可用逻辑桌面验证，不强制打开超出屏幕的窗口。

向导沿用 `--screenshot --page` 的无副作用预览；工作台需要增加项目弹窗/失败状态预览时使用独立样例，不创建真实 SSH、读私钥或改变系统授权。预览与真实功能测试分别记录。

窗口抓图只能证明客户区外观；系统阴影、贴靠、标题栏拖动、跨屏 DPI 与真实终端输入需要独立运行验收。不得用新外观截图覆盖现有稳定性缺口。
