## 用户操作顺序

1. 在同一主机添加两个不同目录的测试项目 A、B，分别打开终端。核对 CLI 显示的实际目录；必要时正常退出 Claude，在远端 PowerShell 执行 `Get-Location`，然后通过新会话重连。不能只用标签提示中的配置目录作为实际目录证据。
2. 在 A、B 分别输入不同文字但暂不提交，切换标签，确认没有串会话。逐一测试中文、退格、复制粘贴、`/` 菜单、Tab、Esc、方向键和 Ctrl+C。记录每一项；未测的项目不能标记通过。
3. 关闭 A 时先取消确认，检查 A 仍可用；再次关闭并确认，检查 B 仍可用。在测试会话正常退出后点击“重新连接”，核对新会话的目录、编号与提示，不将新进程视为恢复旧任务。
4. 第二台主机已授权时，增加跨主机并行检查。切换主机下拉框和标签，确认左侧项目定位正确、已开终端仍对应原主机。
5. 在测试会话中调整窗口、字号及 100% / 150% 显示缩放，检查行列、输入光标和底部提示。记录实际缩放，不以预览截图替代交互。
6. 另建临时测试项目指向不存在目录，确认明确失败且没有在其他目录启动 Claude。连接故障使用独立测试档案，不覆盖正常档案或改动家庭服务配置；未知或变化的指纹不得点击信任放行。
7. 基础检查通过后，在没有需保留任务的测试会话中手动断开测试网络，记录界面响应、SSH 退出／错误和耗时；恢复网络后显式新建连接。不要为验收停止或重配家庭 sshd。
8. 保持测试会话至少 30 分钟，用户自行选择无副作用的输出操作，同时完成 20 次创建／关闭循环，记录操作次数、标签数、是否存在停顿及资源趋势。最终关闭额外标签后留出约 1 分钟观察回落；不要求内存立刻回到首次启动数值。

反馈格式：`场景 / 通过、失败或未执行 / 主机及项目代号 / 现象或截图 / 时间`。出现失败先保留现象和对应时间，不重试到成功后删除原失败记录。

## 资源采样

`tools/SshWorkbench/Measure-WorkbenchResources.ps1` 只读取指定工作台主进程的私有内存、工作集、句柄和线程数，不读取终端内容、连接配置或进程命令行，不终止程序。CSV 是原始数据，不自动判定内存泄漏。

```powershell
Get-Process OrbiDevWorkbench | Select-Object Id, Path
# 将 12345 替换为当前 Release 工作台进程 ID；输出目录须存在，文件不能已存在。
./tools/SshWorkbench/Measure-WorkbenchResources.ps1 -TargetProcessId 12345 -OutputPath ./build-ssh-workbench/ssh04-resources.csv
```

默认采样 30 分钟，每 10 秒一次。提前退出返回 2，不能算完整时长通过。应结合标签数量和输出负载比较稳定区间的趋势，而非只比较首尾两个数值。**本脚本不统计 QtWebEngineProcess、ssh.exe、OpenConsole 等子进程，不能据此宣称整个进程树无泄漏**；真实验收还需在任务管理器观察这些进程的增长和关闭后回收情况。

日志不提交；最终结果应将时长、样本数量、操作次数和趋势摘要补到本文件。没有完成真实关键场景前，不将 SSH-04 标记完成，不提前进入 SSH-05／SSH-06。

已定位：页面原先只接管 Ctrl+Shift+C/V，Qt 视图禁用了右键菜单。现复用原有受控剪贴板入口，增加 Ctrl+V、原生复制／粘贴菜单，并支持有 xterm 选区时 Ctrl+C 复制、无选区时保留 Ctrl+C 中断。没有开放页面任意剪贴板访问或 OSC 52。只读／已退出终端禁用粘贴，保留原有大小上限和输入门控。

专项 Release 自动回归 4/4（含初始化和清理）通过，见 `build-ssh-workbench/ssh04-clipboard-keys.txt`：中文 Ctrl+V、选区 Ctrl+C、无选区中断、菜单粘贴及禁用态；同时验证重复 Shift+Left、Shift+Right 和 Ctrl 组合的客户端输出序列完整。方向键验证只覆盖 Qt→xterm→inputReady 边界，尚未验证 ConPTY→SSH→远端 Claude 的选择行为；该缺陷待家庭端直接运行 Claude 的同操作对照，不标为修复。
