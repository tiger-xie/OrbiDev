# M5-02 会话持久化与运行诊断

## 范围与使用

基于已提交 M5-01 `c9aba16`，本次工作区实现会话元数据 SQLite 存储、Agent 启动迁移、退出码/错误类别和诊断日志轮转。不恢复旧 ConPTY 句柄，不重新启动旧会话，不保存终端录制。Client 与 Agent 须配套更新；M6 Claude Provider 未开始。

继续双击根目录的 Start-RemoteAgent.cmd、Start-RemoteClient.cmd，无需增加启动参数。Agent 配置可选 `data_directory` 为绝对目录；未设置时，使用配置文件旁的 `agent-data`。本机双击脚本因此使用 `.local-run/agent-data`，Debug/Release 共用这份数据。

- `sessions.sqlite`：会话标识、名称、工作区/Provider 标识、状态、UTC 毫秒时间、退出码有效性和固定错误类别。
- `logs/agent.log`：结构化事件；每文件默认最多 1 MiB，最多 5 个归档，保留 7 天。达到大小或跨 UTC 日期轮转，启动和轮转时清理过期归档。
- `agent.lock` 与日志锁：阻止多个 Agent 同时操作同一数据目录。活跃实例持锁时不得手动删除锁文件。

数据库、日志均不记录 PID、令牌、环境、启动命令、输入输出或后端错误原文。会话名称仍是用户提供的元数据，不应主动把秘密写入名称。

## 状态与失败保证

启动先获得数据目录独占锁，再打开数据库。schema 当前为 v2；空库初始化，v1 五列基础表升级为包含诊断字段的 v2。迁移在事务中完成；未知更高版本、物理损坏文件或加载的保留记录字段非法时拒绝启动，不自动删除或重建数据库。

`recover` 在事务中把 Creating/Running/Exiting 转为 Failed，错误类别 `agent_restarted`，退出码标为未知。正常 Exited 的退出码保留。导入管理器后均为 `metadataOnly`：没有后端、写者、订阅者或终端历史，不能附加/输入，仍按当前工作区 ACL 决定可见性。正常停止 Agent 时仍未结束的会话，下次启动同样显示失效，不伪造正常退出码。

新建会话先持久化 Creating，再启动后端；保存失败不启动进程。后续状态或退出元数据保存失败会发出可观察错误，但内存状态继续反映真实进程，不因数据库故障伪造退出。日志写入失败输出固定错误并以非零状态退出 Agent。启动数据库失败也记录安全存储错误类别。

数据库保留最近 128 条终态记录，不裁剪活跃记录；生产 Agent 内存列表最多 32 项。容量满时只淘汰未附加的已结束内存项，不淘汰活跃会话或有订阅者的历史。数据库裁剪与写入/恢复处于同一事务。

诊断日志只接受固定事件、会话 UUID 和 ErrorCode，不接收自由文本。生命周期失败类别为 `agent_restarted`、`launch_failed`、`backend_failed`；具体操作错误继续沿用既有协议安全分类。时间字段使用十进制字符串传递，避免 JSON 数值精度损失；退出码有独立有效性标记。

存储和日志在 Agent 控制线程同步执行，SQLite 锁等待上限 1000 毫秒。没有新增存储工作线程或依赖，磁盘缓慢可能影响服务响应；长时压力留待 M7。flush/事务成功不等于已验证硬件断电安全。

## 验收

1. 启动两端，新建 FakeCli 会话并确认输入正常。
2. 关闭 Agent，再重新启动；Client 重新连接后原会话应显示失效，不显示运行中，尝试打开时提示原进程不可恢复。
3. 新建另一个会话应正常工作，旧会话不会自动启动。
4. 查看数据目录中的 SQLite 文件及日志；日志只有事件类别和会话标识，没有终端内容或设备令牌。
5. 同一配置再次启动 Agent 应明确失败，不影响第一个实例。

自动测试包括 `storage.sessions`（迁移/回滚/坏库/裁剪/安全字段）、`diagnostics.rotation`（大小/日期/保留/拒绝敏感事件/文件失败）、`core.session_manager`（恢复/权限/存储失败/容量）、`protocol.codec`、`client.websocket` 和 `client.window`。`agent.persistence` 启动真实 RemoteAgent 和 FakeCli，强制结束测试 Agent 后重新启动，验证相同 ID 失效且不可附加、数据目录独占以及测试凭据不落盘。

Release 全量构建及 MSVC 静态分析通过，CTest 33/33 通过（162.46 秒）；其中一分钟恢复 62.33 秒、真实 Agent 强制退出重启 0.69 秒。最后补充日志长驻锁设置后，Release 增量构建及 diagnostics.rotation、agent.persistence 2/2 再次通过（1.22 秒）。Debug 首轮 13 组中 12 组通过，client.websocket 暴露 Qt 5.15.2 有界接收缓存半帧等待问题；修复后历史回放与 256 KiB 输入连续 30 轮通过。最终版本 Release、Debug 构建及 MSVC 静态分析均通过；受影响的 agent.websocket、client.websocket、client.remote-terminal、client.reconnect、agent.persistence 两种配置均为 5/5 通过（分别 110.07 秒、150.41 秒）。最终 Debug 一分钟恢复测试通过（74.50 秒），真实 Agent 强制退出重启测试通过（0.87 秒）。以上为分轮验证记录，未将修复前的全量结果当作修复后再次全量运行。修改的 C++ 文件 clang-format 检查及 git diff --check 通过。家庭 Tailscale、真实磁盘耗尽、系统掉电及长期压力未在本卡验收。
