# M4-02 远程终端与 Qt Client

## 范围

基于 M4-01 提交 `f3c9231`，本次连接既有 M3-02 Agent 和真实 FakeCli：Qt Widgets → 本地 xterm.js/WebChannel → 认证 WebSocket → SessionManager → ConPTY。仅实现 M4-02，不接入 Claude、图片附件、自动重连或 SQLite 持久化。网络使用现有 RADP/1，没有新增消息或依赖。

## 启动与人工验收

### 推荐：本机双击启动

先编译 Debug，然后在仓库根目录依次双击：

1. **[Start-RemoteAgent.cmd](../Start-RemoteAgent.cmd)**：自动生成联调配置并启动 Agent。保留控制台窗口；重复启动会提示端口占用，不会结束已有进程。
2. **[Start-RemoteClient.cmd](../Start-RemoteClient.cmd)**：自动传入地址、工作区与设备令牌，进入主窗口后点击“连接”，再点击“新建会话”。不需要自己编辑 JSON 或输入令牌。
3. 在新终端直接输入中文，按回车前即可看见内容，回车后显示 `[TEXT]` 结果；输入 `ansi`、`size` 再回车验证颜色与尺寸；还可新建多个标签、复制粘贴。关闭 Client 后可重新双击启动并连接，从会话树打开已有会话。**停止 Agent 会结束其会话。**

默认使用 `build-local` 中的 Debug 程序、`127.0.0.1:17890` 和 `demo` 工作区，当前启动的是 FakeCli。脚本从构建缓存读取 Qt 路径，临时配置当前进程的 DLL/插件/WebEngine 路径，不修改系统环境变量。

如果编译的是 Release，在仓库终端中执行：

```powershell
.\Start-RemoteAgent.cmd -Configuration Release
.\Start-RemoteClient.cmd -Configuration Release
```

两条命令分别在两个终端运行，或先双击 Agent，再在终端启动 Client。也支持 `-BuildDirectory <构建目录>`。脚本只启动已编译的程序，缺少文件会提示，不自动编译。

配套实现是 [Start-Local.ps1](../tools/local/Start-Local.ps1)。脚本专用配置与测试工作区放在被 Git 忽略的 `.local-run/`：`agent.json` 仅保存设备令牌摘要，`device-token.dpapi` 使用 Windows 当前用户加密，原始令牌不写命令行/日志/明文文件。不同启动沿用同一身份，不要在 Agent 运行时删除该目录。此配置仅供本机联调，不是家庭双端部署或产品配对功能；不要把它复制给其他电脑/Windows 用户。

脚本验证（2026-10-18）：Windows PowerShell 5.1 配置检查、真实 Debug Agent 回环监听及 `auth.hello/session.list` 鉴权通过；脚本启动的 Client 直接进入主窗口，未出现令牌输入框；重复 Agent 和 Agent 未启动两种情况均明确返回错误。业务代码未修改，无需为脚本重新编译。界面交互沿用下方 M4-02 的既有测试记录。

### 手动指定连接配置

先按 [M3-02 Agent 配置](M3-02_AgentWebSocket服务.md) 准备本地配置并启动 RemoteAgent。配置中的 `fake_cli_path` 指向本机构建的 FakeCli，工作区目录必须已存在且向设备身份授权。Client 的工作区参数是 **工作区 ID**，不是公司电脑的磁盘路径。

从 VS 调试时选择 RemoteClient，将参数设为：

```text
--agent-url ws://127.0.0.1:17890/ --workspace demo
```

界面弹出密码式输入框，输入该 Agent 已配对的设备令牌。令牌不是 Claude Token，不放入命令行或仓库，也不写入 QSettings。取消输入框即退出。自动化进程也可通过 `RAD_AGENT_TOKEN` 环境变量传入，应用在创建 WebEngine 子进程前移除该环境变量。

命令行运行需要 Qt bin 在 PATH（VS 调试已配置）：

```powershell
$env:PATH = 'D:/Qt/5.15.2/msvc2019_64/bin;' + $env:PATH
& .\build-local\apps\RemoteClient\Debug\RemoteClient.exe --agent-url ws://127.0.0.1:17890/ --workspace demo
```

地址仅允许显式 IPv4 回环或 Tailscale 100.64/10，禁止公网、DNS、用户信息、查询参数和代理回退；支持空路径或 `/`。跨电脑时填写家庭 Agent 的实际 Tailscale 地址，端口仍由防火墙/Tailscale 权限保护。未执行双端测试前，不将本机回环通过视为跨端验收。

1. 点击“连接”，等待握手及会话列表成功；创建名称和已配置工作区。
2. 新终端应显示 `FakeCli 中文终端验证` 与 `[READY]`。
3. 先确认状态为“持有控制权”。产品 Agent 固定启动 FakeCli 交互模式：直接输入或粘贴中文，提交输入法候选字后立即显示，无需 `echo`。按 Enter 后普通文本显示 `[TEXT]中文`；`echo 中文`、`ansi`、`size` 仍作为测试命令工作。回显由 Agent/ConPTY 返回，Client 不自行补字。
4. 验证退格和 Ctrl+C 取消当前行；FakeCli 交互模式由 Windows 控制台处理行编辑，不提供 Claude 的 `/` 菜单或 Tab 补全。Tab/Esc/方向键的原始传输另由控件与原始模式自动测试覆盖。
5. Ctrl+Shift+C 复制选区，Ctrl+Shift+V 粘贴文本；Ctrl+C 保留为终端中断字节。拖动窗口检查 `size` 返回新的尺寸。
6. 若已有会话显示“只读”，输入不会发送；先“分离”，再从会话树重新打开以申请控制权。真正被其他设备占有时仍保留只读，不抢占。创建三个标签分别输入标识，检查输出不串；分离标签后从树重开。关闭 Client 后 Agent 会话继续运行，终止仍需明确确认。

不带 `--agent-url` 保留 M4-01 的明确模拟模式；`--demo` 自动打开模拟会话，不能用它验收真实终端。配置一旦创建本次客户端不热切换，修改连接参数后重新启动；主机管理/凭据持久化未在本任务实现。

## 处理链路与约束

所有客户端对象在 Qt 事件线程；socket 与 WebEngine 非阻塞。窗口借用 Controller，Controller 借用 IAgentClient，入口保证依次销毁窗口、Controller、网络客户端。关闭 socket 不调用 terminate。

连接先验证地址/凭据格式，然后发送 Authorization 握手、auth.hello 和 session.list；全部成功才显示在线。操作通过 UUID 关联并核对响应类型和会话 ID；创建、附加等异步失败不冒充成功。控制权被占用时可回退只读，UI 禁止写入与终止。当前协议没有退出码字段，真实会话明确显示退出码未提供。

输入由 xterm onData 转 UTF-8 或 onBinary 保留字节，再分块编码二进制帧；序号按附加递增，不重试或跨重连重放。离线、只读、未附加或非运行状态拒绝输入。

输出保留 QByteArray，经 base64 穿过 WebChannel 后恢复 Uint8Array，由 xterm 流式解析 UTF-8/VT。终端加载前每会话最多缓存 1 MiB，控件积压含在途批次最多 1 MiB，每批最多 64 KiB，收到 JS 写入 ACK 才继续。超过上限或 ACK/加载超过 20 秒则明确报错并断开客户端，保留远程进程。输出偏移不连续或收到 overrun 同样断开；有限历史从非零偏移开始时提示缺失，不能宣称精确恢复全屏画面。

网络最多 64 个待决请求、1 MiB 发送积压，连接/请求超时 5 秒；每 5 秒 ping 和附加会话心跳，15 秒无有效 pong 断开。旧连接回调不能影响新连接。客户端不自动重连，M5 再处理恢复体验。M3 服务端现有每连接 4096 个请求上限也包含会话心跳，长时间使用可能因此断开；远程进程保留，当前需手动重连并重新附加，尚未进行长时间耐久验收。

终端页面使用离线 QRC 与锁定的 xterm.js 4.19.0 / FitAddon 0.5.0；禁止外部请求、导航、弹窗和脚本剪贴板访问。远端 OSC 52/8 不获得剪贴板或链接能力。程序不记录终端内容和令牌。旧 WebEngine 的维护风险仍保留。

## 中文输入验收修正（2026-10-18）

用户截图中的“已附加 · 只读”由创建/启动竞态触发：create 成功只表示已受理，进程尚为 creating；立即申请写权收到 busy，旧客户端误按控制权冲突回退只读。新增确定性延迟启动用例，旧代码在 `!session.readOnly` 断言失败。客户端现在等待现有状态广播进入可附加状态，最多 5 秒；断线清理等待，不跨连接自动附加。真正的写权冲突及已退出会话仍允许只读附加。没有修改协议或 Agent，也不抢占其他客户端控制权。

FakeCli 原始输入模式本身不逐字回显，中文输入法候选窗消失后不显示已提交文字不一定是编码丢失。持有控制权时输入 `echo 中文` 并回车应收到 `[ECHO]中文`；Client 不做本地强制回显，以免接入真实 CLI 时重复显示。终端上方已增加提示，处于只读时显示分离后重新申请控制权的操作说明。

本次修复：Debug 构建及 MSVC 静态分析通过；基础界面、网络与真实三标签端到端共 3/3 个 CTest 组通过（42.46 秒）。网络共 11 个行为方法，新增 4 个回归；旧代码失败的立即附加用例修复后通过，UTF-8 中文输入原字节传至后端。已查看更新截图，提示文案和 `[ECHO]中文输入验证` 均可见。Release 受影响目标构建及相同 3/3 个 CTest 组也通过（26.70 秒）。本次未重复全套无关回归；尚未提交 Git。

## FakeCli 退格修正（2026-10-18）

用户确认手动输入期间使用过退格。FakeCli 的原始输入模式此前把 Backspace/DEL 字节直接追加到命令，因此即使修改后本意为 `echo 你好`，也可能得到 `[UNKNOWN]`。现同时处理 `0x08` 和 `0x7f`，从输入缓冲删除一个完整 UTF-8 字符，空行退格无操作。仍不实现 shell/行编辑器，也不在 Client 本地回显。

修改 `tests/fixtures/FakeCli/main.cpp`，在 `tests/integration/WinConPtyBackendTests.cpp` 增加空行退格、命令前缀纠错和已提交中文退格的真实 ConPTY 回归：旧代码失败，修复后 Release 通过。正在运行的 FakeCli 不会自动升级，更新后必须新建测试会话。Debug/Release 的 FakeCli 和后端测试均构建通过（MSVC 静态分析开启），新增真实 ConPTY 退格用例两配置均通过；Debug 用时 1.66 秒。Release 全套 CTest 28/28 通过（77.60 秒）；格式和差异检查通过。尚未提交 Git。

## 交互模式（2026-10-18，替代以上原始模式的手动验收方式）

为解决输入过程不可见的问题，FakeCli 增加 `--interactive` 模式，采用 Windows 原生行编辑和回显，支持输入中显示中文、退格、长行换行及 Ctrl+C 清行。普通非命令文本回车输出 `[TEXT]`，无需加 `echo`；已有 `echo` / `ansi` / `size` 等诊断命令保留。无参数模式继续用于原始字节与控制键自动测试。

FakeCliProvider 使用固定的 `--interactive` 参数，不接受客户端传入启动参数。没有修改 WebSocket 协议、ConPTY 后端或 Client 输入回显逻辑，也不新增依赖。新的 Agent 进程中新建会话才使用交互模式，旧会话不会被自动切换或终止。

验证：新增未回车回显用例在旧模式失败；修复后 Release 全套 CTest 29/29 通过（71.50 秒）。真实窗口端到端验证输入法提交中文在回车前可见、中文退格后普通文本输出 `[TEXT]中文输入验证`、Ctrl+C 取消、复制粘贴、尺寸调整及三个会话隔离。已查看并更新实际截图，最终尺寸 `105x26`。Debug 的 Agent、Client、FakeCli 与受影响测试均已构建，MSVC 静态分析开启；配置、窗口、交互输入和远程终端共 4/4 个 CTest 组通过（51.22 秒）。clang-format 与 git diff --check 通过。复用 Windows 行编辑和已有启动模板，未在 Client 新增本地回显。人工输入法候选窗、超长行取消分支及家庭双机尚未单独验收，仍不代表真实 Claude 功能已完成。
