# M1-01 工程骨架与验证

## 实现范围

本任务建立 RemoteClient、RemoteAgent、RADCore、RADProtocol、RADTests 五个目标。Client 显示最小本地页面；Agent 默认打印说明后退出，尚不是常驻服务。没有连接 Claude、网络或产品化 ConPTY。M0 两个 POC 保持独立。

用户确认当前电脑为公司端，将 M0-03 网络预研延期；后续 Claude 交互允许先在本机验证。网络未通过验收，本轮不提前实现 Provider。

## 文件与调用链

| 文件 | 职责 |
|---|---|
| `CMakeLists.txt`、`CMakePresets.json` | 根构建、独立 POC 开关、VS 2022 x64/v143、分析和测试配置 |
| `apps/RemoteClient/main.cpp` | QApplication → WebEngine 本地页面 → JavaScript 标记检查 → 成功或错误退出 |
| `apps/RemoteAgent/main.cpp` | QCoreApplication → SQLite 内存库 → 中文写入和读取校验 → 释放连接 |
| `core/model/BuildBaseline.*` | 编译基线说明，依赖 QtCore |
| `core/protocol/ProtocolVersion.*` | 协议主版本常量，不实现协议编解码 |
| `tests/unit/BuildBaselineTests.cpp` | 实际加载 Qt 版本、64 位、C++20 和目标链接检查 |
| `tools/packaging/DeployLocal.ps1` | 同机部署及隔离开发 PATH 的运行检查 |

各目录 CMakeLists.txt 管理自身目标。依赖方向及边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。未定义公共会话接口，模型和可测试 Mock 留给 M1-02，避免创建无行为空接口。

## 构建和验收

从仓库根目录的 VS 2022 开发终端执行（CMake 需在 PATH）：

```powershell
$env:QTDIR = 'D:/Qt/5.15.2/msvc2019_64'
cmake --preset local-msvc
cmake --build --preset debug
ctest --preset debug
cmake --build --preset release
ctest --preset release
./tools/packaging/DeployLocal.ps1 -Configuration Release
./tools/packaging/DeployLocal.ps1 -Configuration Debug
```

Qt 路径仅在环境配置中使用。目录名 msvc2019_64 表示 Qt 预编译工具链，项目使用 VS 2022/v143。默认同时构建原有 POC；首次 ConPTY 包下载及离线配置见 M0-01 文档。仅构建产品骨架可添加 `-DRAD_BUILD_CONPTY_POC=OFF -DRAD_BUILD_TERMINAL_POC=OFF -DRAD_BUILD_WINDOWS_BACKEND=OFF`。

本机运行入口：

```powershell
./build-m1-deploy/Release/RemoteClient/RemoteClient.exe
./build-m1-deploy/Release/RemoteAgent/RemoteAgent.exe --smoke-test
```

Client 应显示“工程骨架，未连接Agent”；Agent 应输出 `PASS: agent.smoke` 并返回 0。此处不是最终产品界面，也不能输入 Claude 命令。

VS 可打开 `build-local/RADManager.sln`，选 Debug/x64；默认启动 RemoteClient。可在两个入口的 main 设置断点，切换启动项目后 F5。生成的调试环境包含 Qt bin，但本轮未人工执行 VS 断点验收。

## 实测记录（2026-10-17）

环境已安装：Windows 10 IoT 企业版 LTSC 19044、Qt 5.15.2、VS 2022/MSVC 19.44.35214、SDK 10.0.26100.0。安装情况不等于测试通过。

实际验证：

- 全新 build-local 配置，Debug / Release 编译成功；预设启用 `/W4 /WX` 和 MSVC `/analyze`。
- Debug 10/10 CTest 通过（70.85 秒），Release 10/10 通过（12.78 秒），包含原有 7 项 POC 回归。最后日志调整后 Debug 三项骨架测试再次通过。
- 两种配置的独立部署目录均通过 Client/Agent 烟测。执行时 PATH 仅含 Windows 系统目录，QT_PLUGIN_PATH 清空，并使用本地 qt.conf。
- Client 实际渲染页面并执行 JavaScript；部署目录含 QtWebEngineProcess、resources、translations/qtwebengine_locales 和 platforms 插件。
- Agent 实际加载 QSQLITE，执行内存库建表、参数绑定、中文写入及读取校验。临时移走部署目录 qsqlite.dll 后返回 1，已恢复文件。
- dumpbin 检查 Agent 仅直接依赖 Qt5Core、Qt5Sql 及系统运行库，无 Widgets/WebEngine/WebChannel。
- M1 时关闭两个 POC 的独立配置生成成功，不下载 ConPTY（M2 起还须关闭 WINDOWS_BACKEND）；该配置未另行重复完整编译。

## 未完成与风险

- Debug 部署烟测结束时出现 Chromium `WebFrame LEAKED 1 TIMES` 诊断，进程返回 0；未证明旧 WebEngine 长时间运行无泄漏，需后续稳定性验证，不能把退出码当作资源无泄漏证据。
- 同机部署不代表干净机器发布验证。脚本不打包 VC 运行库（使用 `--no-compiler-runtime`），Debug 包依赖开发机调试运行库；正式发布安装及许可证清单属于 M8。
- 部署脚本不清理已有目录；正式交付前应使用全新目标目录排除残留文件。本轮目标目录为首次创建。
- 未完成 VS 交互断点验收、跨端网络、真实 Claude、会话持有、鉴权与业务持久化。M1-02 尚待实施，整个 M1 不标记完成。

## VS 打开文件夹时的 Qt 调试运行库

文件夹/CMake 模式通过 CMakePresets.json 的 local-msvc 环境将 `$env{QTDIR}/bin` 加入当前进程 PATH；Qt 安装路径仍来自开发机的 QTDIR，不写入业务代码。Debug 自动加载带 d 后缀的 Qt DLL，Release 加载对应发布库，无需改链接目标或混拷 DLL。

已有 VS_DEBUGGER_ENVIRONMENT 用于生成的 Visual Studio 工程；文件夹模式由预设环境覆盖。修改后先停止当前失败的调试，等待 VS 重新配置，再选择 debug 与 RemoteClient.exe 按 F5。若 VS 尚未刷新预设，关闭后重新打开项目文件夹。不要删除 .vs 或构建目录。

依据：[Microsoft：预设环境自动传递给调试配置](https://learn.microsoft.com/en-us/cpp/build/cmake-presets-vs?view=msvc-170#variable-substitution-in-launchvsjson-and-tasksvsjson)。这只配置开发调试环境，正式部署仍需 Qt 插件、WebEngine 辅助程序与资源的完整打包。

本次验证：CMake 预设重新配置通过；直接读取预设中的 PATH 设置启动 Debug RemoteClient/RemoteAgent 的 --smoke-test，两者均返回 0。未自动操作 VS 的 F5/断点；原失败调试需先停止后重新启动。

## Agent 控制台提示与正常退出

当前 RemoteAgent 默认打印“工程骨架，未监听网络”后返回 0，这是现阶段入口行为，不是启动崩溃；SessionManager 已由独立测试验证，尚未接入常驻网络服务。`--smoke-test` 额外执行 SQLite 插件检查。

启动时若附有 Windows 控制台，设置输出代码页为 UTF-8，避免 VS 调试控制台按本地代码页显示 UTF-8 中文而产生乱码；重定向仍写 UTF-8。Debug 重新编译通过，独立隐藏控制台由 CP936 启动验证代码页切为 65001，中文重定向内容和 SQLite 烟测均通过、退出码 0。未自动操作 VS F5 做视觉验收。
