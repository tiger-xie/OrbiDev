## 必须保留的行为

- 当前用户来自实际环境检查；不提供没有实现的跨用户授权按钮。
- 公钥指纹来自校验结果；私钥、附加启动命令和错误输入必须被拒绝。
- 更改输入后，旧指纹、授权摘要与确认选择失效；不能沿用对另一把公钥的确认。
- 只有用户明确确认并点击“应用授权”才写入授权文件；默认不确认、不隐式提权或重启服务。
- 导出内容只包含公开连接信息；预览不检查真实环境、不生成身份、不写授权。
- 完成和失败状态根据业务结果显示；进入结果页不意味着已经应用授权。

## 实现与简化

- 删除家庭端旧文字步骤分支和对应 QSS，复用现有圆标、状态描述、连接线与底栏。
- 环境页分为检查结果和手动调整环境两组；原启动服务、打开可选功能和提权入口保留，均不自动执行。
- 导入页增加当前用户摘要、公钥编辑区、文件导入与只读校验详情。设备备注读取已校验公钥的 comment，不新增编辑或持久化字段。
- 应用页独立显示用户、授权路径、指纹及追加变更，确认复选框默认不勾选。结果页只有授权成功后才启用公开连接信息导出。
- `invalidateImportResults()` 集中清除旧校验、错误和确认，供输入变化与环境重新检查复用。
- 图标 `user.svg` 和 `folder.svg` 保存在 `resources/icon/setup/` 并登记到根 qrc，沿用现有 SVG 加载方式。

步骤状态区分环境检查、公钥校验、应用授权、连接信息就绪；最后一步显示“已就绪”不表示已导出或公司端连接成功。公司端原有四页逻辑保留。

## 截图复查与修正

首轮导入页在常规窗口下将指纹区挤到首屏之外。已收紧用户卡片内边距，将公钥输入区调整为 96～120 逻辑像素，把文件导入按钮与公钥限制说明放在同一行，缩短只读详情区间距。更小窗口仍使用原滚动容器，不隐藏内容或移动固定底栏。

参考图中的可编辑设备备注改为读取已校验公钥备注；“切换用户”改为可见说明，避免误导用户以为可以在本工具内跨账户写授权。

## 手工验收步骤

1. 运行 `Start-HomeSetup.cmd`，检查环境页的结果卡片和手动调整区；只检查不会自动启动服务或弹出提权。
2. 导入公司端公钥，确认当前家庭账户正确；点击“下一步：检查变更”后，显示真实公钥指纹且确认框未勾选。
3. 返回导入页修改公钥，再次校验前旧指纹和确认状态应清空；粘贴私钥或含 `command=` 的输入应留在导入页并显示错误。
4. 核对目标用户、授权文件、指纹及管理员账户提示，再主动勾选并应用。成功后才能导出连接信息，不能返回修改已应用的授权。
5. 100%／150% 下确认文字、编号、输入和按钮没有重叠；缩小窗口后通过滚动查看详情，底栏保持可用。

本轮自动化使用公开测试公钥和临时目录，没有替用户在真实家庭账户追加授权。真实双端验收、跨屏 DPI、Windows 11 行为与此前终端初始化稳定性缺口继续单独记录。
