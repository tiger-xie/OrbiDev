## 2. 构建和启动

在仓库根的 PowerShell 或 VS 开发环境执行；若 CMake 不在 PATH，先使用本机 VS 附带路径：

```powershell
Set-Alias cmake 'D:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe'
Set-Alias ctest 'D:/Program Files/Microsoft Visual Studio/2022/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/ctest.exe'
cmake -S . -B 'build-m0 中文 path' -G 'Visual Studio 17 2022' -A x64 -T v143 -DCMAKE_PREFIX_PATH='D:/Qt/5.15.2/msvc2019_64' -DRAD_ENABLE_ANALYSIS=ON
cmake --build 'build-m0 中文 path' --config Debug --parallel
ctest --test-dir 'build-m0 中文 path' -C Debug --output-on-failure
cmake --build 'build-m0 中文 path' --config Release --parallel
ctest --test-dir 'build-m0 中文 path' -C Release --output-on-failure
```

Qt 路径仅为开发配置。M0-01 单独构建可加 `-DRAD_BUILD_TERMINAL_POC=OFF -DRAD_BUILD_APPLICATIONS=OFF`，不再查找 Qt。C++ 构建使用已保存的前端资源，不要求 Node；ConPTY 首次下载/离线包配置仍参见 [M0-01](M0-01_ConPTY技术验证.md)。

VS 2022 可打开构建目录的 `RADManager.sln`（早期 M0 构建目录为 `RADManagerConPtyPoc.sln`），选择 Debug/x64；请将 TerminalPoc 设为启动项目（M1 工程默认启动 RemoteClient），并从找到的 Qt 安装路径生成调试 PATH。可在 `TerminalBridge::input` 设断点后 F5。该调试配置已生成检查，但本轮未人工操作 VS 断点会话。

本机已准备好可双击的 `build-terminal-deploy/TerminalPoc.exe`。开发目录未部署 DLL 时，使用当前 PowerShell 的临时环境：

```powershell
$env:PATH = 'D:/Qt/5.15.2/msvc2019_64/bin;' + $env:PATH
& './build-m0 中文 path/tools/TerminalPoc/Debug/TerminalPoc.exe'
```

重新生成本机 Release 运行目录：

```powershell
New-Item -ItemType Directory -Force build-terminal-deploy | Out-Null
Copy-Item -LiteralPath './build-m0 中文 path/tools/TerminalPoc/Release/TerminalPoc.exe' -Destination build-terminal-deploy
& 'D:/Qt/5.15.2/msvc2019_64/bin/windeployqt.exe' --release --no-compiler-runtime './build-terminal-deploy/TerminalPoc.exe'
& './build-terminal-deploy/TerminalPoc.exe' --self-test
```

本机部署目录包含 Qt DLL、`platforms/qwindows.dll`、`QtWebEngineProcess.exe`、`resources/`、`translations/qtwebengine_locales/`。不得只复制 EXE。这里复用本机已有 MSVC 运行环境，**不是可对外发布的安装包**；干净机器的运行库、完整 Qt/Chromium 许可及源码义务由发布阶段验证。

## 3. 行为和维护契约

输入链路为 xterm `onData` → `bridge.input` → 本地模拟器 → `output` → xterm `write`。全部 C++ 对象在 GUI 线程，页面、channel、bridge 使用 Qt 父对象生命周期；profile 比 page 长寿。不存在业务层公共接口或协议变更。

- 模拟命令：`help`、`echo 文本`、`ansi`、`clear`、`flood`；其他命令显示不支持。Ctrl+C 中止模拟输出、清空命令，方向上键显示 `[UP]`。
- 单次输入上限 65,536 个 UTF-16 单元，命令行上限 8,192；超过限制显示状态提示。模拟器不是完整 shell 行编辑器，其他控制序列仅报告收到。
- `flood` 生成 24,000 行，每批最多 2,048 行、约 200 KiB。xterm 处理完输出才调用 `ackOutput`，前一批全部确认后发下一批，避免一次把全部输出排进浏览器。滚动缓冲为 3,000 行；收到所有行不等于无限保存历史。
- 压力输出期间普通输入会被拒绝并提示；Ctrl+C 仍可中止。确认机制仅供本地 POC，不是远程会话重传/序号协议。
- ResizeObserver 触发 FitAddon，字号范围 10–30，实际列行通过 WebChannel 回传状态栏。尚未接入真实 ConPTY resize。
- Qt 读取/写入系统剪贴板，粘贴使用 JSON 编码，不拼接原始输入成 JS。网页没有直接剪贴板权限。
- 主页面只允许指定的 QRC URL，禁用新窗口和远程/本地文件访问，请求拦截器仅允许 QRC/data，CSP 禁止网络连接。无命名 profile 不持久化网页缓存。
- 自动测试启用 Chromium `--disable-background-timer-throttling`，避免测试窗不在前台时定时器节流；普通运行保持默认策略，未关闭沙箱。自测不是吞吐性能基准。
- `--screenshot <PNG路径>` 抓取窗口客户区后退出；`--self-test --screenshot <路径>` 自测后抓图并按结果退出。截图不证明输入法、系统窗口边框或高 DPI 交互正确。

环境：本机 Windows 10 IoT 企业版 LTSC x64（19044），Qt 5.15.2 MSVC x64，VS 2022 v143。运行时 userAgent 报告 `QtWebEngine/5.15.2 Chrome/83.0.4103.122`。

| 检查 | 本次结果及边界 |
|---|---|
| Debug / Release 编译、moc、资源生成、链接 | 通过；C++20、`/W4 /WX /analyze`。`/analyze:external-` 排除 Qt 外部头，项目源码仍分析 |
| 完整 CTest | Debug、Release 各 7/7 通过，包括原 6 项 ConPTY 回归 |
| Qt 终端自动测试 | ANSI 文本与颜色单元格属性、中文、拆分 UTF-8 字节、清屏重绘、字号和容器 resize 回传、模拟 keydown Ctrl+C/上键、粘贴输入、选择文本复制 |
| 高吞吐 | 24,000 行编号连续、无重复或缺失、末行已写入、完成后能继续 echo。Debug 终端测试约 40.54 秒，Release 约 7.86 秒，含启动及其他测试，不是纯输出速度 |
| 同机独立运行目录 | 进程 PATH 仅保留 Windows 目录时自测通过，前端全部 QRC；没有通过断网实验或网络抓包证明整个 Chromium 进程零网络活动 |
| 实际视觉检查 | 已查看 1120×740 客户区截图：工具栏、中文欢迎文本、青色光标及尺寸状态显示正常 |

| 操作 | 期望 |

## 6. 版本和风险

为可复现构建固定 **xterm.js 4.19.0 / FitAddon 0.5.0**，真实本机 WebEngine 自动测试已通过；人工项目仍以第 5 节为准。两包均为 MIT，许可随 QRC 资源保留，package-lock 保存官方 npm 来源与完整性值。

两个旧包名均已 deprecated，Qt 5.15.2/Chromium 83 也存在维护风险；本机兼容成功不表示安全支持或所有 CLI 都兼容。后续升级必须重跑本机验证，不静默替换版本。POC 不含网络鉴权、真实进程、会话持久化或产品皮肤切换。

API 依据：本机 Qt 5.15.2 官方文档 `qtwebchannel-javascript.html`、`qwebengineurlrequestinterceptor.html`，以及 [xterm 官方插件指南](https://xtermjs.org/docs/guides/using-addons/)；Qt 5 API 优先以本机版本文档为准。
