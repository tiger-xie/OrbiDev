# OrbiDev SSH 首次配置与家庭授权

本工具用于公司电脑准备 SSH 身份、家庭电脑导入公钥。使用已选定的石墨灰／青绿界面。它不启动 Claude，不替用户确认工作区信任，也不运行常驻配对服务。

本阶段保留原 ProjectLauncher、RemoteClient、RemoteAgent 和既有未提交修改。新工具配置单独保存，不覆盖旧项目名称、路径、勾选状态或 `home_dev`。内嵌 SSH 终端是下一阶段，本工具完成配置后仍可使用原启动器。

## 启动与携带到家庭电脑

1. 开发机双击根目录 `Build-SshSetup.cmd`：Release 构建、测试、部署 Qt 并打包。
2. 公司端双击 `Start-SshSetup.cmd`。它只读旧启动器主机设置；已有密钥请在第二步选择，避免重新授权。
3. 家庭端使用 `build-ssh-setup/OrbiDev-SshSetup-Release.zip`，解压整个压缩包，再运行 `OrbiDevHomeSetup.exe`。不能只复制一个 EXE。同机检查可以双击 `Start-HomeSetup.cmd`。
4. 包内不含用户配置、密钥、旧项目数据或测试生成的身份。不要从用户身份目录复制文件进发布包。

VS 调试可打开构建生成的 `build-ssh-setup/OrbiDevSshSetup.sln`，选择 `OrbiDevSetup` 或 `OrbiDevHomeSetup` 为启动项目；目标已配置 Qt 调试搜索路径。Debug 构建可执行 `tools/SshSetup/Build.ps1 -Configuration Debug`。原工程的启动项目和构建目录不变。

## 公司端：首次设置

- **检查环境**：检测系统 OpenSSH 与 Tailscale；Tailscale 在线只说明网络组件状态，不代表家庭 SSH 已授权。
- **创建本机身份**：新用户进入此步骤时生成专用无口令 Ed25519 身份，目录位于当前用户 LocalAppData 下的 OrbiDev 应用数据目录。生成前限制目录权限，生成后收紧并检查私钥权限。重复使用同一身份；残缺密钥、错配公钥或过宽目录权限返回错误，不覆盖已有文件。
- **保留已有密钥**：选择本机私钥路径，工具只读取对应 `.pub` 并调用系统 OpenSSH 校验，不展示私钥内容，不修改原权限。当前已有密钥必须为无口令且文件权限符合检查要求；加密私钥暂不支持。
- **授权家庭电脑**：复制或导出公钥，仅将公钥交给家庭端。私钥不能分享。
- **测试连接**：输入家庭地址、用户、端口，或导入家庭工具生成的 JSON。核对家庭端显示的完整主机指纹并勾选确认，再测试。
- **保存配置并完成**：只有认证和远端 Claude 命令查找通过才能完成。配置保存在用户应用配置目录的 `connection.json`，不写入旧启动器 JSON。

已有主机信任记录时可不填指纹，OpenSSH 仍使用严格检查。填写指纹时，工具获取家庭 Ed25519 主机公钥并与核对值比较，只有一致才为本次测试建立临时信任文件；不修改系统 `known_hosts`，指纹变化会阻止连接。第一次使用原外部终端启动器时仍可能出现它自己的主机信任提示，应核对同一指纹。

连接测试使用选定的密钥，禁用 SSH agent 与额外 SSH 配置身份，避免其他密钥造成“已授权”的假象。SSH 别名只用于解析目标主机和默认用户；代理跳转、特殊 SSH 配置不属于此直接 Tailscale 连接版本。用户名支持常见本地账户名称，暂不支持带反斜杠的域账户表示法。

## 家庭端：导入授权

1. 用实际运行 Claude 的 Windows 账户打开工具，点击检查环境。
2. 粘贴公司端公钥或导入 `.pub`，下一步会显示公钥指纹和拟修改的授权文件。
3. 核对账户、路径和公钥指纹，勾选确认，再点击“应用授权”。重复公钥不会重复追加；原有授权行与限制选项保留。
4. 普通账户使用用户授权文件；默认管理员规则使用 `ProgramData/ssh/administrators_authorized_keys`，该文件可对其他管理员账户生效，界面会提示。
5. 如需权限提升，点击“以管理员权限重新打开”，使用同一 Windows 账户完成 UAC，再重新导入并确认。程序不会提升后直接写入，也不会在后台静默应用。
6. 完成后导出公开连接 JSON，回公司端导入测试。文件写入完成不等于远程登录验收通过。

工具在应用前重新检测并与预览比较。账户、授权路径、服务状态、地址、端口或主机指纹变化时停止写入。已有授权文件先备份为同目录 `.orbidev-backup-...`，写入或权限处理失败尝试恢复原内容及 DACL；若回滚失败会显示备份位置，需人工恢复。

## 未安装／自定义 SSH 环境

若出现读取 `sshd_config` 失败，请使用新版“检查环境”后的“复制检测结果”。新版会给出完整路径、Windows 错误码及服务状态，区分文件不存在、读取权限不足、文件被其他程序独占。管理员重开仍失败不等于需要再次提权。

默认路径是 `%ProgramData%/ssh/sshd_config`。微软说明，文件不存在时，sshd 在服务启动时生成默认配置；因此“服务已安装”不等于“已经完成首次启动”。先核对服务状态和安装位置，不要复制默认文件覆盖现有配置，也不要为了消除提示放宽目录 ACL。工具仅检测，不会自动创建配置或启动服务。

本版本针对**已经安装并运行的 Windows OpenSSH Server**。缺少组件时提供 Windows 可选功能入口与诊断；不自动安装、重启服务、修改默认 Shell 或防火墙。因此没有“自动系统安装已验证”的承诺。

首次安装请按微软官方说明安装 OpenSSH Server，由家庭电脑管理员完成服务启动和防火墙配置：只允许本人的 Tailscale 来源与回环访问，不启用向公网暴露的端口映射。先检查已有规则，避免新建规则与已有宽泛允许规则叠加；准备好后回到工具重新检测。现有可工作的 SSH 环境无需执行这些安装步骤。

遇到自定义服务启动参数、Include、复杂 Match、非默认 AuthorizedKeysFile 或自定义 HostKey 等配置，工具停止自动写入并说明原因，不猜测目标。此时应由了解该配置的人手工添加公钥。

官方依据：[微软 Windows SSH 密钥管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)、[服务配置](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)。

## 验收边界

### 手动确认启动 SSH 服务

环境页点击“启动 SSH 服务…”或双击完整安装包中的 `Start-SshService.cmd`。脚本先检查安装及运行状态，输入 `Y` 后申请 UAC 并执行 `Start-Service sshd`；其他输入取消。未安装时提示安装 OpenSSH 服务器，失败保留错误。完成后重新点击“检查环境”。

脚本不设置开机启动、不重启正在运行的服务、不修改 Shell 或防火墙；SSH 监听范围沿用已有配置。首次启动可能由 OpenSSH 生成配置和主机密钥。真实 UAC 和服务启动需在家庭机验收；脚本测试模拟未安装、已运行、取消确认和取消提权，不修改本机服务。

自动化测试只在临时目录创建测试密钥、修改测试授权文件；不在真实家庭机添加授权或修改服务。真实 UAC、家庭机普通／管理员账户、两端连接仍需按以上流程验收。

待人工检查：新身份生成并授权、旧身份复用、重复导入、错误公钥、指纹不一致、断网与认证失败。验证“网络／服务／认证／Claude”四个结果；不能只看一个绿色提示。

`--screenshot <路径> --page 0..3` 为无副作用预览，仅渲染界面，不运行检测或生成密钥；灰色按钮表示预览被禁用。该截图不能作为真实 SSH 验收结果。
